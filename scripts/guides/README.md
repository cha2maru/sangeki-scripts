# 脚本家の指針（guides）

脚本ごとに、中身を知る Claude が書く脚本家の指針。ユーザーの案（2026-10-04）:
「先にあなたがシナリオを読み取り、人間のプレイヤーにも有益なプレイ指針と、それを機械的な定義になおしたものを先に作り、それを読み取ることでうまく動けるようにする」。

- `<脚本id>.md` — 人間向け。負け筋、仕上げの日、おとり、同時に出す脅威、隠す役職、ループごとの方針。根拠（どの事件・役職・特性を使うか）を書く。
- `<脚本id>.json` — 機械向け。自動の脚本家（SearchMastermind の `guide`、league の `searchguide`）が読む。ファイル名は脚本ファイルの `id`（d27.json）。

## JSON の書式（すべて省略可）

```json
{
  "script": "designed/d27",
  "routes": [
    {"id": "Y_CONTRACT", "via": null, "w": 1.5, "note": "本命"},
    {"id": "MURDER", "via": "C08", "w": 0.5, "note": "ラバーズが割れるので後回し"}
  ],
  "cards": [
    {"loop": [1], "day": [1], "target": "C10", "card": ["INT2"], "w": 1.0, "note": "初日に通れば契約で確定"},
    {"loop": [2, 3, 4, 5], "day": [2], "target": "C12", "card": ["PAR+"], "w": 0.5, "note": "不安拡大を起こす"},
    {"day": [1, 2], "target": "C07", "card": ["PARX"], "w": 0.3, "note": "おとり"}
  ],
  "incidents": {"SPREAD": {"par_target": ["C19"], "int_target": ["C10"]}},
  "hide": ["C17", "C06"]
}
```

- `routes`: 負け筋の重み。`id` と `via` は play_cli の「勝ち筋（距離の近い順）」に出るもの（`via` が無い筋は null）。`w` を筋の評価に掛ける（既定 1）。
- `cards`: 置くと加点する伏せ札。`loop`・`day` は省略で全部。`card` は脚本家の札の名前（PAR+ PAR- PARX GWX INT1 INT2 MV_V MV_H MV_D）。手に合えば `w` を足す。
  おとりもここに書く（加点が無いと、自動の脚本家は効果の薄い札を置かない）。
- `incidents`: 事件の効果の置き先の優先（左から順に、合法な最初のもの）。書かない事件は今まで通り評価で選ぶ。
- `setup`: ループの準備で脚本家が決めること（`{"scholar": "int"}` 学者の特性、`{"init": {"C18": "HOS"}}` 手先の初期エリア）。書かない項目は今まで通り評価で選ぶ。
- `lock_hide`: そのループの勝ちが確定したら押さずに隠す（漏れの重みを何倍にするか。searchhide と同じ。10 が目安）。
- `hide`: 割らせたくない人物。この人物が要の筋（via）の重みを 0.3 にする（最終ループは 1）。
